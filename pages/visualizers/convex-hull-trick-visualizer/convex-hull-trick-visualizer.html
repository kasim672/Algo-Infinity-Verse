Convex Hull Trick

Most lines you add will never be the answer to anything. Discard them immediately.

Given a growing set of lines y = mx + b, most recurrences only need the minimum (or maximum) y at a query x. Instead of checking every line, maintain only the ones that can ever win — the lower envelope — and answer queries in O(log N).

📐 Why Dominated Lines Vanish

📉

The Lower Envelope

Sort lines by slope. A line is only ever optimal (for a minimum query) over some contiguous range of x — the envelope is exactly the sequence of lines that are each optimal somewhere.

🚫

The "bad" Test

Given three consecutive lines by slope, the middle one is dominated (never optimal anywhere) if the intersection of the outer two lines occurs at an x where the middle line is already worse. This single geometric test is checked every time a new line is added.

🔍

Binary Search on the Hull

Because the envelope's optimal x-ranges are sorted, binary searching for which line wins at a given x takes O(log N) — dramatically cheaper than evaluating all N lines directly.

🌲

Li Chao Tree for Non-Monotonic Queries

If lines arrive in arbitrary slope order or queries aren't sorted, a Li Chao Tree — a segment tree where each node keeps only the best line for its x-range — handles insertion and query both in O(log(range size)) without needing the sorted-envelope structure at all.
