SWIM Protocol

Scalable Weakly-consistent Infection-style Group Membership

How do massive clusters detect dead nodes without a central monitor? The SWIM protocol uses a clever combination of direct pings and indirect relays. If a direct ping fails, the node asks peers to double-check before declaring a failure, drastically reducing false positives caused by temporary network glitches!

✨ The SWIM Protocol Mechanics

📡

Direct Probing

Every node periodically picks one random peer and sends a standard ping. If the peer responds with an ack, the node is considered healthy. This random probing eventually covers the entire cluster without needing a centralized tracker.

🔗

Indirect Relays

If the direct ping times out, it doesn't immediately declare failure! The connection might just be glitchy. The prober asks $K$ random peers to send an indirect ping on its behalf. If any relay gets an ack, the node is saved from false suspicion.

⏳

Suspicion Sub-Protocol

If all indirect probes also fail, the node is marked as Suspected (not dead yet!). This status is gossiped to the cluster. If the node doesn't refute this suspicion before a final timeout expires, it is permanently marked as Dead.
