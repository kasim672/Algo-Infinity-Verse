⏳ Time-Travel Data Structure

Persistent Segment Tree

Query the past. Branch the future. K-th smallest in O(log N).

Instead of copying the entire array for every update, a Persistent Segment Tree creates a new root and shares unmodified subtrees with previous versions. It only takes O(log n) new nodes per update! This allows you to query any historical version effortlessly, unlocking powerful algorithms like finding the K-th smallest element in a range.

⏳ The Magic of Persistence

🌲

Path Copying

During an update, instead of mutating existing nodes, we create a new node. Since a segment tree has depth O(log N), only the nodes on the path to the updated leaf need to be copied. This is only log(N) new nodes!

🔗

Subtree Sharing

For any node not on the direct path to the update, the new version simply points to the old node. The old version remains perfectly intact. Both versions share the unmodified subtrees in memory.

📚

Prefix-Frequency Arrays

For the K-th smallest problem, we build the tree such that Version $i$ holds the frequency of elements in $A[0 \dots i]$. Therefore, $Version[R] - Version[L-1]$ gives the exact frequencies for the subarray $A[L \dots R]$.

🎯

K-th Smallest Query

To find the K-th smallest, we traverse both $Version[R]$ and $Version[L-1]$ simultaneously. We look at the left child's sum. If it's $\ge K$, the answer is in the left subtree. Otherwise, we subtract that sum from $K$ and go right.
