✨ How Bitmask DP Works

🔢

Sets as Integers

Instead of passing a Set(0, 2, 3) through recursion, we use binary: 01101 (which is 13 in decimal). The $i$-th bit is 1 if city $i$ has been visited. This allows us to use an integer array for lightning-fast DP memoization.

⚙️

Bitwise Transitions

To check if city $j$ is visited: (mask & (1 << j)). To add city $j$ to the visited set: mask | (1 << j). These bitwise operations compile down to single CPU instructions, making the state transitions incredibly fast.

📈

Strict Dependency Order

A state with $K$ visited cities strictly depends on states with $K-1$ visited cities. By grouping masks by their population count (number of 1 bits), we naturally satisfy the Topological Sort required for iterative DP.

🗺️

Optimal Tour Extraction

Once dp[full_mask][end_city] is computed, we simply check which incoming transition provided that minimum cost, and trace backwards through the bitmasks (flipping off bits one by one) to extract the path.
